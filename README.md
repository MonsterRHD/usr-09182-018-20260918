# 创新项目里程碑拨付系统

面向机器人与关键零部件研发资助的**里程碑证据拨付平台**。核心立场：

- 不按报销单被动拨款——拨付绑定可协商、可版本化的**阶段承诺**与满足承诺的**技术证据**；
- 不因一次试验失败否定高风险研发——失败作为一等证据结构化留痕，其价值永久保留并支撑路线决策；
- 拨款必须**证据完整**与**职责分离**同时满足；
- 项目暂停/终止后，设备与未用资金的**处置义务不免除**；
- 每笔资金都能回溯到**批准当时**冻结的证据快照，后续证据更正不改写历史。

## 领域模型（契约即文档）

[`contracts/domain.json`](contracts/domain.json) 定义：术语表、六类角色与职责分离规则、21 种事件目录、
里程碑状态机、四个拨付闸门、知识产权规则、敏感字段矩阵、11 条不变量与验收选取规则。

事件契约：`event_id`（全局唯一）/ `occurred_at`（带时区）/ `entity_id` / `version`（实体内严格递增）
/ `actor_id` / `payload.type`。**状态只能由事件流重放得到，事件一经追加不可变。**

## 业务闭环

1. **登记 → 预算科目 → 阶段承诺**：研究目标、验收指标、证据要求与预算科目绑定成里程碑；
   承诺可协商（`MilestoneNegotiated` 留版本），双方承诺生效后方可执行（`MilestoneCommitted`）。
2. **证据与失败**：提交证据、技术核验；试验失败走 `TrialFailed`（假设/现象/根因/学到的价值），
   必须写明 `learned_value`。更正走 `EvidenceCorrected` 追加新版本，原件标记 `superseded` 但永不删除。
3. **路线切换**：`RouteSwitchRequested` 必须引用失败证据 → 外部独立评审 → 资助机构批准
   （`RouteSwitchApproved`），产生新承诺版本与**预算重估新版本**（旧版本全部保留）；
   切换前的知识产权归属在批准条件中明确不变。
4. **拨付双闸门**（`service.evaluate_payment_gates`）：
   - `gate_evidence_complete`：当前承诺版本的每项必需要求都有已核验接受的有效证据（失败留痕也算证据）；
   - `gate_separation_of_duties`：提交人 / 核验人 / 批准人 / 执行人互不相同；
   - `gate_state`：里程碑已承诺且未暂停/终止；
   - `gate_budget`：金额对应挂钩科目，不超过重估后承诺额度。
   批准时 `PaymentApproved` 冻结**证据快照**（证据 ID + 版本 + 事件内容 sha256）；
   `PaymentExecuted` 由不同于批准人的财务执行。
5. **暂停 / 终止**：`MilestoneSuspended` 必须同步登记设备与未用资金的处置义务；
   终止后未决义务仍然 open；履行须 `DisposalObligationFulfilled` 留证。
6. **验收**：只按当前生效承诺版本指标判定，须有外部验收评审；
   验收示范项目由 `projections.acceptance_candidates` 自动选取——**中途切换过技术路线且最终达标**。

## 代码结构

| 路径 | 职责 |
| --- | --- |
| `app/event_store.py` | 仅追加事件存储：幂等、版本连续、时区校验、事件指纹 |
| `app/state.py` | 事件流重放状态（每类事件一个 apply；更正不覆盖原件） |
| `app/service.py` | 命令与全部业务闸门（角色鉴权、双闸门、路线变更、预算重估、暂停义务、验收） |
| `app/projections.py` | 只读投影：付款↔证据快照追溯、验收选取、失败价值台账、处置义务、预算历史、角色脱敏全卷 |
| `scripts/build_fixtures.py` | 生成验收场景事件流 |
| `fixtures/events.json` | 两个示范项目共 41 个事件 |

## 验收场景

- **ROBO-2026-007 机器人谐波减速器**：阶段一正常拨款后证据被更正（旧付款快照冻结不变）；
  阶段二合金钢柔轮 6200h 失败 → 留痕 → 外部评审 → 切换碳纤维复合材料柔轮 →
  预算重估（承诺 200 万 → 170 万，科目间调剂、总额不增）→ 新证据达标 → 按新承诺版本拨款并验收通过。
- **DRV-2026-011 伺服驱动器**：指标未达标迭代中，因团队变动暂停（**非因失败被否定**）；
  老化箱封存义务已履行留证，未用资金退回义务仍 open。

重新生成夹具：

```bash
python3 scripts/build_fixtures.py
```

输出会展示验收选取结果、每笔付款绑定的承诺版本与证据快照（含事后更正标注）、处置义务状态。

## 测试

```bash
python3 -m unittest discover -s tests -v
```

34 项测试覆盖：事件契约与幂等/版本/不可变、四个闸门各自的拒绝路径、职责分离冲突、
失败留痕与价值保留、更正不覆盖原始事实、付款快照冻结、路线切换三前提（失败证据+评审+重估）、
旧路线证据不充抵新承诺、暂停义务在终止后仍有效、按角色脱敏，以及夹具端到端验收选取与资金追溯。
