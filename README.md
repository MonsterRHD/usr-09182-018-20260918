# 创新项目里程碑拨付

面向机器人与关键零部件创新项目的里程碑拨付系统。资助机构不按报销单被动拨款，而是把研究目标、技术证据与预算科目协商为**阶段承诺**，按承诺与证据拨付；一次试验失败不会否定项目，失败的价值被保留并支撑路线变更。

## 结构

- `contracts/domain.json` — 领域契约：事件五要素（event_id / occurred_at / entity_id / version / payload）与三条不变量
- `milestone_funding/events.py` — 事件模型，构造时即按契约校验（带时区时间、正整数版本等）
- `milestone_funding/store.py` — 只增事件存储：重复 event_id 拒绝（同一事件只生效一次），版本按实体严格递增（更正只追加、不覆盖原始事实）
- `milestone_funding/domain.py` — 事件折叠出的项目投影（里程碑、证据、失败、拨款、义务等）
- `milestone_funding/service.py` — 业务命令与规则校验
- `milestone_funding/permissions.py` — 角色视图：权限不足的角色（外部专家、未识别角色）拿不到预算、金额、知识产权归属等敏感字段
- `tests/` — 不变量测试、拨付闸门测试与验收场景

## 核心规则

- **阶段承诺**：登记研究目标与预算科目后，协商生成里程碑承诺；承诺总额不得超出科目总额
- **拨付双重闸门**（同时满足）：
  1. 证据完整 —— 里程碑要求的每类证据均有"已采纳"版本；
  2. 职责分离 —— 技术评审与财务审批两道批准，审批人不得是申请人，同一人不得兼任两道审批
- **资金锚定证据**：执行拨付时快照当时批准的证据（标识+版本），此后证据更正不影响已拨款项的锚点
- **失败留痕**：试验失败记录经验教训；路线变更必须关联已记录的失败，未拨付里程碑同步重估预算并保留重估历史
- **暂停义务**：项目暂停即生成"设备处置"与"未用资金"两项义务，未履行完毕不得验收
- **验收**：全部里程碑达成且义务履行完毕方可验收，失败记录随验收归档保留

## 运行

```bash
python3 -m unittest discover -s tests -v
```

`tests/test_acceptance_scenario.py` 是完整业务样例：灵巧手项目从谐波减速器路线切换到腱绳驱动，重估后续预算后逐里程碑达标，最终验收通过。
